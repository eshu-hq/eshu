## Question A: collector #118 (unreadable lastModified stamp in a feed record)

Ruling: API fallback with a flagged class. #118 closes on an evidence comment.

- ADR-0005 covers the decision. The #157 arbiter did not weigh the window-path
  skip by name, so this ruling is the attribution for #118. A bounded skip moves
  the cursor past a record nobody committed, which ADR-0007 forbids and ADR-0005
  calls a silent false negative. Skip only wins when the API is down, and that is
  when the lost record is permanent.
- The #118 constraint holds. A probe-time hit routes to the API as
  `nvd_feed_probe_failed` (`collector repo: nvd_feed_selector.go`). A hit after
  selection ends retryable as `nvd_feed_record_unreadable` with zero API requests
  (`collector repo: nvd_feed_scan.go`, `collector repo: nvd_feed_collect.go`).
- Follow-up 1, a full probe read per window claim, and a negative cache for it:
  accepted limit, no issue. The caught-up exit runs before the probe, a healthy
  covered claim already reads the feed twice, a cache needs state that survives
  across claims, and a corpus run found 0 unreadable stamps in 425,782 year-file
  records.
- Follow-up 2, no progress while the API is down and a feed record is unreadable:
  accepted limit, no issue. Documented in `collector repo: docs/concepts/README.md`
  and pinned by `TestNVDFeedUnreadableStampWithAPIDownMakesNoProgressUntilItRecovers`.
- One P3: add one Consequences sentence to ADR-0005 and "#118" on its Arbiter line
  in the next collector PR that touches `docs/decisions`.

## Defects found while verifying

Each needs an issue and work in this goal. The issue numbers filed from this
ruling are in the table that follows the list.

1. Baseline stalls on real data (collector and Eshu; blocks baseline enable). The
   2025 year file holds 1,402 records at `2026-10-18T21:10:00.120` that fold to
   17,478 facts. The 2026 file holds 1,581 records at `2026-10-26T21:10:00.170`
   that fold to 14,156 facts. A group over 10,000 facts refuses forever
   (`collector repo: nvd_baseline_chunk.go`, ADR-0004 item 2), so the planner never
   leaves 2025. Requirement: record-atomic always, but a same-stamp group may drain
   across chunks by (stamp, CVE ID). This needs one shared design ruling first
   because it changes the mirrored baseline contract. Proposed tests:
   `TestNVDBaselineGroupOverFactCapDrainsAcrossChunks`,
   `TestPlanNVDBaselineResumesInsideAnInstant`.
2. Seed rotation mid-year (Eshu, on the #10746 path; blocks baseline enable). Core
   holds `baseline_seed_stale` on any digest change (`nvd_baseline_planner.go`),
   but the refresher re-pins 2025 and 2026 daily and each year takes days to
   replay, so the hold would fire within about a day. Inferred, because #10746 is
   unbuilt. Proposed tests: `TestPlanNVDBaselineResumesAcrossForwardSeedRotation`,
   `TestPlanNVDBaselineHoldsOnSeedRollback`.
3. Window path sheds the same two groups (collector; this is #10671's own drain).
   Both stamps are ahead of the cursor at 2026-10-17T20:18Z. ADR-0004 item 7 and
   ADR-0007 item 5 shed a group over the fact cap, loudly but for good. First step:
   establish whether 10,000 facts is a host limit or only a collector constant.
   Proposed test: `TestNVDWindowGroupOverFactCapCommitsEveryRecord`.
4. Pacing figure is off by about 10 times (Eshu docs). Measured: 5,039,862 facts at
   1,256 budget bytes each. The byte cap binds at about 1,670 facts a chunk. That
   is about 3,000 chunks, or about 63 days at one per 30 minutes.
   `10728-baseline-pacing.md` section 2 says about 301 claims and 151 hours.
   Baseline completion cannot be a closing condition for the #10671 goal.
5. Re-scope Eshu #10735 and #10736. Both cite the unmerged addendum. #10735 is
   still needed, minus its collector #107 split-record clause.
6. Year seed is not wired to the window path (collector; outside #107).
   `collector repo: nvd_feed_selector.go` passes a zero horizon and only the
   baseline reads the seed. Amendment 1 of the #10671 ruling required
   year-set-served windows before QA enable. The cursor to M0 gap moves only
   through the API today.
