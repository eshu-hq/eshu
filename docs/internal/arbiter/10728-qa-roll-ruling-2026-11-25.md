   successful Publish run). Pin 1 carries 1,220 commits, migrations 313–344

   345–349 only, crossing the revert + #11334 cure + #11372 boost.
2. **Pin 2 requires an explicit API decision in the IaC PR — silent
   arg-ignoring is rejected.** The chart renders `eshu-api -addr …`
   when `api.coreBaseURL` is set; QA sets it. The in-tree binary
   parses neither flag and serves the monolith. The PR must either unset
   `api.coreBaseURL` (explicit monolith path, phase-5 re-planned in the PR
   text) or prove a different rendered command the binary honors. Also
   verify the chart probe path (`/health` vs `/healthz` flip in range).
3. **Target-selection rule (Pin 2; Pin 1 fixed above).** Newest `main`
   commit at IaC-PR-open time satisfying: contains `b52bcc64cd`; Publish
   Image run completed success (build-and-push, promote-moving-tags,
   verify-reproducibility); two stable crane digest reads plus per-arch
   image-config revision labels equal to the commit; tree-max migration
   ≤349 and no Dockerfile binary-shape change, else re-audit. As of the
   ruling that evaluates to **`0d7943b2c5`**. `f64d07358a` is disqualified
   (its Publish run still in progress — pinning an in-flight manifest is
   forbidden). Once the Pin-2 PR opens, the target is frozen.
4. **Forward-only migration risk is acceptable on QA, with rollback split
   at the first new claim.** Sweep of 313–349 found no `DROP COLUMN/TABLE`,
   rename, or type change; the only UNIQUE is on a new table (322); the
   only triggers are new dirty-mark triggers (338) tolerant of old writers;
   backfills idempotent; 324/326 delete mirror-only rows. No writer
   quiesce. Rollback pins: Pin 1 → `sha-db8f76e8…`; Pin 2 → the Pin-1 tag
   plus reverting the D2 chart change in the same PR. But an old binary
   after new-binary claims leaves stale mirror rows unreconciled: rollback
   approved only if the new reducer claimed nothing; after the first new
   claim the path is forward-fix unless orphan-heal coverage is proven.
   Never soak old binaries on the new schema.
5. **PreSync stays the mechanism** (syncWave `-10`); no standalone schema
   Job. Bare CONCURRENTLY runs with lock_timeout disabled, so a stuck
   build burns the full hook deadline — hence C2.
