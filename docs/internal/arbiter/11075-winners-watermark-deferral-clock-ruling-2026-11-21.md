2. Candidate (a) ADOPTED (semantics): stale iff watermark < required AND now - first_deferred_at > winnersWatermarkMaxWait (strict >, 30min unchanged). 3. Mechanism = waiting-ledger read (#11080 refined Q1-b), NOT the phase-2 failure-details marker + claim +3 columns. (iii) The ledger already locks in the established work_item_id order; the claim-shape change churned ~27 fakes for no semantic gain. The phase-2 handoff's tests, telemetry design, and full-loop proof shape carry over; only the anchor source swaps. Spec: new startup-wired port on Handler (nil = startup error, fail closed — no silent fallback to the cycleStart clock, ever); read keyed exactly as waitingKeyFor for WaitingKindWinnersWatermark (same key derivation, shared code, not a copy); row absent = first deferral = not_ready; read error = visible retryable non-wait failure (distinct from not-found).
