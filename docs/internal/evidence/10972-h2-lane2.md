## Methodology notes (live-primary behavior, all read-only)

- Cold reads of hot ids exceed the 10s guard (count batches 40–93s cold;
  shipped 163k-row singleton ~93s cold-throttled at ~15MB/s I/O). Canceled runs
  do not warm the cache. Every timed claim above is post-convergence
  (back-to-back warm+measure per set); cold runs are disclosed, never counted.
- The live pool churns under production traffic: a set warmed minutes earlier
  can evict before measurement (batch5 run 1: 8.4s second-touch). Timed runs
  execute back-to-back with their warmup. This is substrate behavior identical
  for before/after shapes, not a Lane-1b effect.
- Working-set scale: one 5-heavy-id count batch touches ~450k heap blocks
  (~3.6GB); the union of all 56 screen candidates exceeds shared_buffers, so
  the screen warmed each batch immediately before timing it.
- The shipped singleton on the current-top 163k-row advisory id completes in
  9.2s warm — within the guard but breaching the 2s p95 bar with no headroom,
  and unreliable across pool states (two warmed timeouts observed). The routed
  read on the same id: 16 statements at 250–326ms.
