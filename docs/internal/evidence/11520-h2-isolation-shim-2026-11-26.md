Tested the cheapest shim for the H2 hot-id lane split on disposable Postgres: EXPLAIN ANALYZE BUFFERS on the 5-id hottest chunk plus a bounded isolated-vs-shipped replay. Worst warm median 278 ms against the 5.0 s bar with identical findings (isolated union == shipped == fact oracle), all binding constraints intact — verdict PROCEED on the caller bar, with implementation in a separate lane.

Generic plan shape (first-run text): cve arm `Bitmap Index Scan on
supply_chain_impact_finding_supports_cve_idx` (85,400 rows), advisory arm
`Bitmap Index Scan on ..._advisory_idx` (400 rows), member arm `Bitmap Index

of the supports table. Custom plan keeps the advisory index scan and the
member GIN bitmap and seq-scans only the cve arm (85,400 of ~206k rows, ~41%
selectivity — the planner's legitimate local choice at fixture scale; on QA's
8.6M supports the btree bitmap wins, per the #11430 guard proof's 721 ms
custom-plan median on the real worst id). The abort bar (a plan skipping the
advisory/member GIN arms) never triggered in either mode.

## (b) Bounded replay: isolated-vs-shipped identity

| arm | holders | timing (final run) |
|---|---|---|
| shipped single statement (5 ids) | 1,809 | 229.2 ms |
| isolated hot singleton (`CVE-2024-0001`) | 1,680 | 34.7 ms |
| isolated cold 4-pack | 129 | 4.4 ms |
| isolated union (hot + cold) | **1,809 — MATCH** | 39.0 ms sequential total |

Findings identity: the isolated union equals the shipped set exactly (1,809
holders; hot 1,680 + cold 129, disjoint as routed). The hot id mass (84,200)
sits above the 10k routing threshold and the cold pack's combined mass
(~4,000) below it, so the measured masses reproduce the
`planHolderReadStatements` partition (hot singleton + one cold pack, every id
in exactly one statement).

Shipped-vs-fact-oracle on the golden family corpus: `{CVE-HOT, CVE-3,
GHSA-HOT, GHSA-7, adv-foreign-hot}` → 12 = 12; `{CVE-1, CVE-2, GHSA-1,
adv-foreign-2, own-8}` → 10 = 10. No mismatch.

## Binding constraints: all intact

No timeout raised (10s guard used throughout), no worker or batch change, no
batch-size-1 (the 5-id chunk is preserved; the 1+4 split follows the shipped
10k invariant), the guard stays on every statement, claim/key fences and the
admitted set untouched (no queue, lock, lease, or claim SQL touched — no
production file touched at all), parallelism bound 4 unchanged.

## Verdict: PROCEED on the caller bar, implement nothing here

Bounded per-statement cost (worst warm median 278 ms vs 5.0s bar, worst run
313 ms vs 10s guard) with identical findings (isolated union == shipped ==
fact oracle) and no binding-constraint break: the STOP conditions did not
trigger. No implementation follows in this lane.

Notes for the coordinator. (1) The diagram's step-2 ratio gate (≥ 2.0 on phase
medians) is N/A by construction for H2: both arms run byte-identical
statement text, so there is no faster statement to prove — isolation buys
scheduling decoupling, not a cheaper plan. For the record, the sequential
isolated total on this fixture (39.0 ms) ran 5.9x under the un-split 5-id
single (229.2 ms) because each statement plans independently; that ratio is
fixture-scale (41% cve selectivity) and transfers no claim to QA. (2) The
diagram's step-3 contention cut (≥ 10 min vuln-filtered QA pass sample) still
needs a QA read-replica run and was not attempted here — local disposable only
by task order. (3) QA guard medians from #11430 (generic 848 ms, custom
721 ms on the real worst id) remain the production-shape cost reference; the
local numbers above re-prove boundedness on the same query text, not QA
latency.
