# #6738 projector active-generation and attempt fencing

Root-Cause Evidence: Read-only ops-qa samples on 2026-09-18 found two git scopes whose `active_generation_id` pointed to a `superseded` generation while the successor remained `pending`. The pointed source-local work had `failure_class=projector_superseded_by_newer_generation` and the same update time as the generation demotion. `ProjectorQueue.Heartbeat` demoted both work and generation before successor Ack could move the scope pointer. A disposable PostgreSQL regression reproduced the pointer gap before the fix: one active pointer, one superseded pointed generation, and one pending successor. A second RED regression showed a stale `Fail` could clear the pointer after heartbeat revoked its claim. A third RED regression showed same-owner reclaimed attempts could still Heartbeat, Ack, or Fail the newer claim because `lease_owner` is shared by replicas.

The conflict domain is `scope_id`; `fact_work_items.work_item_id` and the monotonically increased `attempt_count` identify one claimed attempt. Production projector and ingester queues use one-minute and five-minute leases respectively, with heartbeat at one third of the lease; worker counts are unchanged. Claim increments `attempt_count` and returns it with the work item. Heartbeat, retry, terminal Fail, and Ack now require both owner and attempt count. Ack first updates and checks the claimed work row in its existing five-statement transaction, then promotes generation and pointer; a zero-row update rolls back before any publication or post-commit hook. Terminal Fail locks the owned work row before changing generation or scope; a stale or duplicate Fail changes zero rows. The retry path also rejects zero-row stale attempts. Heartbeat still supersedes older work, but retains a published active generation until successor Ack; unpublished pending generations become superseded immediately. A terminal failure of the active generation's own re-projection still fails that generation.

No-Regression Evidence: The local real-PostgreSQL RED/GREEN tests use isolated schemas. Before the fix, the published heartbeat case had one superseded old work row, one superseded active generation, one pointer still naming it, and one pending successor. Afterward, the work is superseded while the old generation remains active and pointer-consistent; successor Ack changes the old/new generation states to superseded/active and moves the pointer. If the successor calls real `ProjectorQueue.Fail`, its work becomes dead-lettered and the old active pointer remains. A duplicate old Ack or Fail after heartbeat is rejected and changes zero rows. With the same `LeaseOwner` but current `attempt_count=2`, stale attempt 1 Heartbeat, Ack, and Fail each reject and leave the running work, active generation, and pointer unchanged. The pending-old case still demotes both work and generation. The liveness fixture changed from `stuck=2, aging=6` to `stuck=1, aging=7` while the recovery sweep continues to exclude the newer-pending scope. The hosted PostgreSQL contention workflow now enrolls both live test families; its hermetic enrollment guard failed before the workflow edit and passed afterward.

Performance Evidence: A disposable PostgreSQL 18 `EXPLAIN (ANALYZE, BUFFERS)` fixture with 10,000 unrelated scope generations and one superseded scope kept the heartbeat statement's same plan and one work/one generation row updates: 0.087 ms before and 0.100 ms after in single samples. A separate 10,002-active-generation liveness fixture measured 1.328 ms before and 1.403 ms with the final shared eligible-intent/successor-set query. The first correlated successor candidate was rejected: it crossed PostgreSQL's JIT cost threshold and took 20.425 ms even after limiting actual successor probes to two. These small local samples establish query shape and reject that candidate; they do not claim ops-qa throughput. Ack still uses five SQL statements and one transaction, with no added round trip; its work-row update moved first. The terminal Fail statement adds a work-row lock and runs only on failure. No worker-count, batch, or timeout setting changed.

No-Observability-Change: Existing structured `projector work superseded by newer generation` logs include the scope and failure class. `fact_work_items` retains status, failure class, owner, attempt count, and updated time for exact-item inspection; `/admin/status` reports source-local pending/retrying/dead-letter backlog and active-generation aging/stuck counts. `eshu_dp_generation_liveness_recovered_total`, `eshu_dp_generation_liveness_failures_total`, and projector retry telemetry show recovery and retry movement. Rejected stale operations return `ErrProjectorClaimRejected`; operator-facing status and logs remain the diagnosis path. The existing two stale ops-qa pointers require successor Ack or a deliberate recovery after this change is deployed; this code change prevents new pointer gaps but does not silently rewrite historical rows.
