# #7533: scheduled PostgreSQL live proof enrollment

The `postgres-scheduled` runner owns 96 exact named tests in 57 live files. The same job runs daily at 04:35 UTC, on manual dispatch, and for pull requests changing its exact enrolled inputs. It uses one digest-pinned PostgreSQL 18.6 service. Crossplane, infra inventory, and ACK/completion use separate fresh databases. The three disposable groups use an administrative DSN to `postgres`, then the shared test helper creates a random database from template0 and cleans it up. These rows have class `verified_scheduled`; they are no longer counted as legacy scheduled exemptions. ## Hosted proof retention

Every hosted attempt writes `manifest.json` with the run URL, ID, attempt, event, reviewed PR head SHA, actual checkout SHA, event SHA, inventory and selected-source checksums, pinned image, and observed PostgreSQL version identity. A final step rechecks that manifest and all six Go JSON streams. The workflow uploads them together as a 14-day artifact, including after a failing proof step. Before merge, record the passing PR run and artifact URL and verify its reviewed head and checkout SHAs. The local manifest and bundle check used synthetic run metadata with the owned PostgreSQL 18.6 fixture and retained Go streams. Its manifest says `local_simulation`; the hosted verifier rejects that origin, and GitHub Actions forbids the local allowance. This local check is not hosted execution evidence.
