# Query methodology pilot evidence (#7881)

The pilot extends the existing query manifests and execution seams. It adds
eight executable contracts and disposable PostgreSQL/Neo4j proof. It does not
rewrite a production query or add a production index.

## Calibration before blocking activation

Performance Evidence: the preliminary PostgreSQL run at candidate
`d02dd225775a96b8da7eb5e52a9f1c1dc75b9780` used PostgreSQL 18.6, 20,001
owner rows, 20,000 source facts, two scopes and all 96 parameter cases. The
64 production SQL variants passed independently computed fixture results.
The run took 13.50 seconds. The largest inclusive root buffer count was
96,767 blocks, with zero temporary blocks. The maximum normal sample was
179.342349 ms. The work ceiling is 150,000 root blocks with zero spills;
the existing cloud-resource interactive ceiling remains 2,000 ms.

The preliminary Neo4j 2026.08.1 run at the same candidate exercised 488
request shapes, 280 emitted texts and 282 statement cases on two repositories,
duplicate imports, an orphan historical file and 128 skew imports. It took
101.705 seconds. The largest total operator database-hit count was 2,413
on each side, and the largest root output was 134 rows. Maximum normal
cold-plan samples were 144.741 ms on base and 134.110 ms on candidate;
warm maxima were 2.798 and 2.739 ms. Sixteen bounded Cartesian-product
alerts per side were retained. The work ceilings are 5,000 hits and 1,000
output rows; normal timing has a 2,000 ms ceiling.

These are calibration records, not a speedup claim or final-head receipts.
Each backend verified that its base and candidate production query/schema
sources were identical. PostgreSQL used base `bd9472ed560b9667fbb10d5e29a1022dacccdf96`;
Neo4j used base `ee0d7d5e5bb1d3ffd6474bb3011d8a6484798459`. Do not compare
their totals or combine them into a cross-backend latency claim.
Cold preparation resets plans and retains warm storage buffers; it does not
prove a cold operating-system cache. Final evidence must be regenerated by
the combined runner after the last commit and validated against current HEAD.

The complete targeted runner subsequently passed at candidate
`333ece7f687d0d737c354ede4aebd5d8ccd0dc79` against base
`ee0d7d5e5bb1d3ffd6474bb3011d8a6484798459` in 291 seconds (4m51s).
Its legacy Neo4j PROFILE phase took 57.845 seconds and confirmed 24 indexes.
PostgreSQL took 12.15 seconds and Neo4j pilot proof took 114.20 seconds.
Both typed artifacts passed the complete-set and current-commit validator.
Work maxima stayed at 96,767 root blocks, zero spills, 2,413 operator hits
and 134 root rows. This calibrates the expanded blocking stage's runtime;
it does not replace artifacts for a later head.

## Operators and failure evidence

Observability Evidence: the calibration JSON artifacts retain emitted text,
safe fixture parameters, commit/engine/schema/index identities, independent
expected and actual identity ledgers, full plans, per-node work and repeated
normal timings. The expanded artifacts also retain complete database statement
row arrays for each normal sample and check their canonical JSON byte size
against the declared family ceiling. The graph report also counts every
request's graph reads and enforces a three-read bound.
The latency harness reports each selected HTTP/MCP operation and every concurrent
status/result, plus workers, peak client requests in flight, wall time,
throughput and p95. The dedicated job archives host load and container CPU/memory.
Production API/MCP telemetry is unchanged because production reads are unchanged.

The planted removed-grant and physically absent-index cases failed, followed
by clean restored passes on both engines. Six real Neo4j unbounded/bounded
profiles exercised the escaped #7335 rule. The MCP cycle-cap test used the
production server's HTTP handler and proved terminal partial truth. Static
mutations cover absent/stale artifacts, missing required variants, permissive
authorization operators and joins, unknown grammar and ambiguous counters.

The #6794 status regression remains tied to PostgreSQL work budgets, not only
latency. Its existing work-metric proof is in
[the #6797 shim](6797-read-api-work-metric-shim.md). Selected parameterized GET,
POST and MCP checks now reject a wrong HTTP 200 payload, including warmups.
Focused concurrent tests also pass under the race detector.

Independent review exposed two gaps in the new proof. A self-consistent HTTP
200 catalog with an invented verb passed; the regression now fails unless all
21 expected verb identities, their six layers and zero seeded counts match.
A helper-only change failed to select live proof; the real selector regression
now requires both stages for `live-gate-lock.sh`. Each new regression failed
before its correction and passed afterward. Timing comments now describe the
first counted pass after warmups and retain the legacy JSON field name without
claiming a cold cache.

## Reproduce and archive

Run `bash scripts/verify-query-methodology.sh --static` for deterministic
contracts and `bash scripts/verify-query-plan-regression.sh` for the complete
targeted live stage. The latter produces `coverage.json`, `postgresql.json`,
`neo4j.json` and raw graph cases under `.proof-artifacts/query-methodology/`.
Static coverage is an inventory snapshot of staged bytes, not a paired commit
artifact. Only the live stage freezes `identity.json` and validates both
committed revisions before backend producers run.
The PR and merge-group job archives those files. Their validators require
current base/candidate commits and reject reuse when a producer omits output.

Run the supported-backend dedicated stage with the existing latency script:

```bash
ESHU_GRAPH_BACKEND=neo4j GATE_RUNS=3 \
GATE_CONCURRENT_WORKERS=4 GATE_CONCURRENT_REQUESTS=20 \
GATE_LATENCY_REPORT=methodology-latency.json \
GATE_CONCURRENT_REPORT=methodology-concurrency.json \
GATE_WORK_REPORT=methodology-work.json \
bash scripts/verify-read-api-latency-gate.sh
```

Keep its default scale: 800 scopes, 150,000 nodes per infrastructure label,
150,000 IaC facts with large payloads and 2.5 million shared projection intents.
Reserve a quiet host and a 45-minute time bound. Archive resource observations
and exact exits alongside the reports. Preserve the required NornicDB lane.

NOT_CHECKED in this calibration note: the final combined-head live runner and
the default-scale concurrent latency stage. Their required receipts are the
current generated artifacts and PR proof, not these preliminary timings.
